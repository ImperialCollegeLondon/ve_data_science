A scenario is one complete setup for running the Virtual Ecosystem at a site: a grid, a
time period, a configuration and a set of input data files. Scenario names combine the
site and a number, such as `maliau_2`.

## The scenarios

Four scenarios are defined. All use square 100 m grid cells (1 hectare each), start on
1 January 2010, run for 11 years (2010 to 2020) and update monthly.

| Scenario | Grid | Area | Lower-left corner (x, y) | Upper-right corner (x, y) |
| --- | --- | --- | --- | --- |
| `maliau_1` | 50 × 50 cells | 25 km² | 491559.3, 520298.8 | 496559.3, 525298.8 |
| `maliau_2` | 10 × 10 cells | 1 km² | 495559.3, 524298.8 | 496559.3, 525298.8 |
| `safe_1` | 50 × 50 cells | 25 km² | 574900, 524000 | 579900, 529000 |
| `safe_2` | 10 × 10 cells | 1 km² | 575400, 526700 | 576400, 527700 |

Coordinates are in metres in the UTM Zone 50N projection (EPSG:32650).

Each small scenario sits inside the large one for the same site. `maliau_2` is the
north-east corner of `maliau_1`. The small grids run quickly, which makes them useful
for development, testing and sensitivity analysis.

## Where scenarios are defined

The grid and timing for each scenario are written to a grid definition file:

* `data/derived/site/maliau/maliau_grid_definition.toml`
* `data/derived/site/safe/safe_grid_definition.toml`

The Maliau file is generated by `analysis/site/maliau_site_definition.py`. To change a
grid, edit the scenario settings in that script and run it again. Do not edit the
grid definition file by hand, because the script overwrites it.

Each grid definition includes the grid extent, the centre coordinates of every cell,
and ready-made `core.grid` and `core.timing` settings for the model configuration.
Analysis scripts read these files so that every module builds its inputs on the same
grid.

## What a scenario folder contains

Scenario files live under `data/scenarios/<site>/<scenario>/`.

```text
data/scenarios/maliau/
  soil_litter_metadata.toml     sources for each soil and litter input variable
  maliau_2/
    change_log.txt              dated record of changes to the input data
    config/
      config.toml               model configuration
      config_latest_release.toml
    data/                       input data files, shared through Globus
```

The input data files are not stored on GitHub. See
[Data with Globus](../using_globus.md) for how to download them.

For `maliau_2` there are two configurations. `config.toml` is for the development
version of the Virtual Ecosystem and `config_latest_release.toml` is for the latest
release. The [Python setup page](../uv_setup.md) explains how to switch between
versions of the model.

The script `analysis/site/build_config_maliau_2.R` rebuilds the `maliau_2`
configuration from its parts and writes `config_regenerated.toml`, so that the result
can be compared with the committed configuration.

## Recording changes

Every change to a scenario's input data is recorded in that
scenario's `change_log.txt`. Add new entries at the top, in this form:

```text
2026-09-08
- Module: Soil & Litter
- Author: Your name
- Files changed:
  - data/scenarios/maliau/maliau_2/data/soil_maliau.nc
- Changes made:
  - What changed and why.
- References:
  - PR or issue
```

The change log is the quickest way to find out why results from a scenario differ
between two dates.
